## 宿題

- 取り組んだレベル：発展

- 変えた設定やデータ：

  元の架空FAQではなく，講義で扱うAIエンジニアリング関連の専門用語を説明するタスクに変更した．

  `scripts/make_sft_dataset.py` により作成した `glossary_sft.jsonl` を使用した．データセットは58種類の用語に対し，各2種類の質問を用意した計116件の質問・回答ペアで構成される．

  学習データは `messages` 形式で，ユーザーの質問に対して専門用語の定義を回答するようにした．

  学習条件は以下のとおりである．

  | 項目 | 設定 |
  |---|---|
  | 基盤モデル | Qwen/Qwen3.5-0.8B |
  | 学習方法 | LoRA（量子化なし） |
  | 学習データ数 | 116件 |
  | LoRA rank | 16 |
  | LoRA alpha | 32 |
  | 学習率 | \(2\times10^{-4}\) |
  | エポック数 | 20 |
  | 学習ステップ数 | 300 |
  | 最大生成トークン数 | 96 |
  | 生成方法 | Greedy decoding |

  116件すべてを学習に使用し，学習時の検証データは設けなかった．評価には別途作成した質問を用いた．

- 結果（比較表や数字）：

  学習は20エポック，300ステップで正常に終了した．Trainerが記録した学習時間は約781秒．  
  全ステップの平均Training Lossは約0.3698，最後のログに記録されたTraining Lossは約0.0686だった

  学習前後で同じ3問を入力し，回答内容を比較した．

  | 評価対象 | 学習前 | 学習後 |
  |---|---|---|
  | 学習済みの用語（LoRAの定義） | LoRAを「ローカルな小さなモデルを追加する手法」と説明するなど，不正確だった | 基盤モデルの重みを固定し，低ランク行列を学習する仕組みを説明できた |
  | 学習していない言い換え（LoRAで更新する重み） | 基盤モデル全体を更新しないことは説明したが，仕組みの説明に不正確な箇所があった | 追加した低ランク行列を学習する点を説明できた．ただし表現に不自然さが残った |
  | 架空の用語（NebulaRank-17） | 実在するAI分析プロジェクトの第17版であるかのように回答した | 講義で使用するランキングモデルであるかのように回答した |

  学習済みの用語とその言い換えについては，回答内容の改善が確認できた．
  一方，架空の用語については，学習前後のどちらも実在するものとして説明しており，ハルシネーションは解消しなかった．

- ファインチューニングが向く場面・向かない場面についての考察：

  LoRAによって用語の定義をモデルに学習させることで回答の正確性が改善した．また，学習時とは異なる質問表現に対しても，学習した知識を利用した回答が得られた．
  このことから，ファインチューニングは，特定の専門分野における用語や回答形式など，比較的固定された知識・振る舞いをモデルに習得させたい場面に適していると考えられる．一度学習すれば，推論時に用語集全体を入力する必要がない点も利点である．
  しかし，今回の架空用語に対する実験では，ファインチューニング後も根拠のない説明を生成した．これは，特定の知識を学習させることが，未知の情報を適切に判断する能力の獲得を必ずしも意味しないことを示している．

  また，ファインチューニングでは知識を更新するたびに追加学習が必要となるため，頻繁に内容が変更される情報には適していない可能性がある．
  一方，RAGなどの検索を組み合わせる手法では，回答時に外部の用語集や文書を参照できる．そのため，知識の追加・更新が容易であり，参照元を確認できるという利点がある．ただし，検索対象から適切な情報を取得できなければ誤回答する可能性があり，検索処理や参照文書の管理も必要となる．
  以上より，回答形式や安定した振る舞いの学習にはファインチューニングを使用し，更新頻度が高い情報や根拠の確認が重要な知識にはRAGを使用することが有効だと考えられる．両者を組み合わせる方法も考えられる．
